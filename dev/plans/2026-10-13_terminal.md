# Passer au terminal sans casser le graphique

État : en cours. Étape 0 faite le 13 octobre 2026. La mise à niveau vers
Ubuntu 26.04 est reportée au changement de distribution (14 octobre 2026) :
on construit sur Kubuntu 24.04, Plasma 5.27, Emacs 29.3 et kitty 0.32.2, une
fois 24.04 stabilisée (`dev/plans/2026-10-13_ubuntu-26.04.md`).

- Constats et sources : `dev/audits/2026-10-13_terminal.md`, puis
  `dev/audits/2026-10-13_terminal-details.md` (versions, presse-papier,
  couleurs, touches prises par kitty, sessions, Claude Code et Emacs).
- Choix faits et leur raison : `dev/decisions.md`.

## Ce qu'on cherche

Aujourd'hui, un clic dans Dolphin ouvre chaque fichier texte dans un nouvel
Emacs graphique ; Dolphin sert à gérer les fichiers ; Claude Code, git et les
sessions SSH vers les VM passent par Konsole, sans Emacs.

Le but : un point d'entrée par projet, depuis lequel on navigue dans les
fichiers, on ouvre l'éditeur, Claude Code et une zone d'exécution, et on
passe simplement d'une session active à l'autre. Les choses doivent être
lisibles d'un coup d'œil, comme dans un IDE moderne (éditeur, exécution,
prompt de Claude), sans bloat. Quitter KDE et changer de distribution viendra
beaucoup plus tard.

## Principes

- **Le graphique reste l'outil de tous les jours** tant que le terminal n'est
  pas confortable. On bascule le jour où il l'est, pas avant.
- **Un seul `init.el`.** Ce qui ne concerne que le terminal s'active dans
  `tty-setup-hook` (lancé à l'ouverture de chaque cadre terminal) ou derrière
  `(display-graphic-p)`. Un même daemon sert les cadres graphiques et
  terminal : `emacsclient -c` et `emacsclient -t` partagent les buffers.
- **La cohérence avant la richesse**, pour les raccourcis comme pour le
  reste (`dev/decisions.md`).
- **Mesurer à chaque étape** : `python3 dev/tty-check.py` après chaque
  changement d'`init.el`, et dans le terminal lui-même, `cat -v` puis la
  touche, pour voir ce qu'il envoie.
- **Chaque étape est réversible**, et chaque nouveau paquet entre dans
  `package-selected-packages`.
- **Pas de snap.**

## Étapes

0. **État des lieux** (fait) : la config marche déjà en terminal ; seul le
   terminal doit envoyer les bonnes séquences. Complété le même jour :
   versions, presse-papier, couleurs, conflits de touches.

1. **Raccourcis : inventaire et grammaire commune**, avant toute config de
   kitty
   - Inventorier ce qui existe et ce qui sert vraiment : KDE
     (`~/.config/kglobalshortcutsrc`), Firefox (raccourcis standard), Emacs
     (`init.el`, avec `cua-mode`), kitty (défauts relevés dans l'audit),
     Claude Code (documentation), et les conventions des tilers (touche
     Super), en vue du futur gestionnaire de fenêtres.
   - Proposer une grammaire par couche, puis la discuter avec Lou : quel
     modificateur pour les fenêtres et bureaux, lequel pour les conventions
     d'application, lequel pour les onglets et panneaux du terminal.
   - Ambiguïtés déjà repérées :
     - trois niveaux d'onglets : Firefox (Ctrl+Tab, Ctrl+PgUp/PgDn), les
       onglets de buffers d'Emacs (`centaur-tabs` sur C-<prior>/C-<next>),
       les onglets de kitty ; plus les fenêtres de KDE ;
     - C-<tab> vaut `other-window` dans Emacs et « onglet suivant » presque
       partout ailleurs ;
     - Ctrl+C copie dans Emacs (`cua-mode`), mais interrompt un programme
       dans un terminal, où copier passe par Ctrl+Maj+C ;
     - une dizaine de combinaisons Ctrl+Maj d'Emacs que kitty prend par
       défaut (tableau dans l'audit).
   - Livrable : un tableau unique des raccourcis retenus, dans `dev/` pour
     l'instant. Si l'étape s'alourdit, elle passe dans son propre plan
     (`dev/plans/AAAA-MM-JJ_shortcuts.md`).

2. **kitty, minimal**
   - Installer kitty par apt (0.32.2, avec `kitty-terminfo`).
   - `~/.config/kitty/kitty.conf` : police Hack 15, couleurs `#1c1c1c` et
     `#E0E0E0` comme Emacs, `clear_all_shortcuts yes`, puis seulement les
     raccourcis retenus à l'étape 1 (au minimum copier et coller).
   - `~/.config/kitty` devient son propre dépôt public, comme `.emacs.d`.
   - Vérifier avec `cat -v` : Maj+flèches, Ctrl+Entrée, Ctrl+Maj+Entrée.

3. **Emacs dans kitty**
   - Le daemon : activer `emacs.service` (systemd, fourni avec Emacs), avec
     `COLORTERM=truecolor` dans son environnement, seul moyen mesuré
     d'obtenir les couleurs 24 bits sous Emacs 29. Ce réglage vit hors du
     dépôt : l'ajouter à « Hors dépôt » dans `CLAUDE.md`.
   - Dolphin ouvre les fichiers avec « Emacs (Client) » (`emacsclient`) au
     lieu d'« Emacs (GUI) » : un seul Emacs, les fichiers arrivent comme
     buffers. Habitude qui change : fermer une fenêtre ne quitte plus Emacs.
   - `kkp`, activé par `tty-setup-hook`, avec
     `kkp-restore-legacy-keys-around-subprocesses` pour que C-g interrompe
     toujours les appels bloquants.
   - Presse-papier : mesurer `xclip` (méthode `emacs`) dans les deux sens
     depuis un cadre kitty, et le passage par Klipper.
   - Corriger `:background nil` dans `themes/apropospriate.el`, et les
     bindings d'org écrits avec `iso-lefttab` (`init.el`, lignes 1104
     et 1106).
   - Vérifier `frame-background-mode`, `centaur-tabs`, la souris et les
     couleurs dans kitty.
   - `dev/tty-check.py` : lancer son daemon sans `COLORTERM`, comme
     systemd, sinon il ne voit pas le problème des couleurs.
   - Utiliser `emacsclient -t` à côté du graphique, noter ce qui gêne.

4. **Le point d'entrée par projet : essais et propositions**
   Trois pistes à essayer sur une vraie tâche d'un même projet, en notant ce
   qui gêne :
   - **kitty au centre** : une session kitty par projet (onglets ou panneaux
     pour `emacsclient -t`, Claude Code et un shell), bascule d'un projet à
     l'autre par `goto_session` (kitty 0.43 et plus, donc binaire officiel
     à tester) ; les fichiers par dired, ou plus tard yazi.
   - **Emacs au centre** : un daemon ; `project.el` pour passer d'un projet
     à l'autre, dired pour les fichiers, Claude Code dans Emacs
     (claude-code-ide.el, avec eat ou vterm), shell dans Emacs ; kitty ne
     fait qu'accueillir `emacsclient -t`.
   - **Le graphique amélioré** : Emacs graphique comme aujourd'hui, mais un
     seul (étape 3), et Claude Code dans kitty à côté.
   Critères : clarté, nombre de couches à tenir en tête, cohérence des
   raccourcis, robustesse, qualité d'affichage de Claude Code (le README de
   claude-code-ide.el signale un scintillement avec eat et vterm).
   Dans toutes les pistes : `EDITOR="emacsclient -t"`, pour que Ctrl+G dans
   Claude Code ouvre le prompt dans Emacs. Monet (Claude dans kitty, relié à
   Emacs par `/ide`) demande Emacs 30 : écarté tant qu'Emacs reste en 29.
   Avant d'essayer claude-code-ide.el, couper
   `claude-code-ide-enable-execute-code`, qui laisse Claude exécuter du Lisp
   dans Emacs.

5. **SSH**
   - Éditer sur un serveur : TRAMP depuis l'Emacs du poste
     (`/ssh:serveur:/chemin`), avec la config habituelle ; rien à installer
     sur le serveur.
   - Sessions shell sur les VM : depuis kitty. `TERM=xterm-kitty` est
     souvent inconnu d'un serveur : vérifier `kitten ssh`, qui y copie le
     terminfo, ou un repli sur `xterm-256color`.

6. **Plus tard** : yazi à côté de dired, puis gestionnaire de fenêtres et
   distribution (KDE n'a plus de correctifs dans Kubuntu 24.04 après
   avril 2027). Les versions d'Emacs et de kitty se revoient à ce
   moment-là, avec Plasma 6.
