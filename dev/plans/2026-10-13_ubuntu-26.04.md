# Mettre le poste à niveau vers Ubuntu 26.04

État : reportée le 14 octobre 2026 au changement de distribution
(`dev/decisions.md`). Le bilan et l'inventaire de l'interface Plasma
resteront utiles ce jour-là. À la place, on stabilise 24.04 (section
suivante). Lou lance chaque commande dans son propre terminal ; Claude
vérifie entre les étapes.

## Stabiliser 24.04

1. Garder le PPA kisak-mesa, pour Minecraft (`dev/decisions.md`). Mesa y
   est restée à moitié mise à jour : le 12 mars 2026, `apt upgrade` n'a fait
   passer que le pilote Vulkan (et VDPAU) en 26.0.1, le reste en 25.3.5
   (journal d'apt) ; la cause n'est pas établie. Les quatre mises à jour de
   Mesa précédentes par ce PPA (septembre 2025 à février 2026) étaient
   complètes.
2. Appliquer les mises à jour : `sudo apt update && sudo apt upgrade`, puis
   redémarrer. Simulé le 14 octobre 2026 : 190 paquets, aucune suppression,
   aucun paquet retenu ; tout Mesa passe en 26.2.4 (amd64 et i386), avec
   `libllvm21`. `apt full-upgrade` donne ici le même résultat. Vérifier ensuite : `glxinfo -B` affiche Mesa 26.2.4 ;
   Plasma, une vidéo, QGIS, Minecraft. R passe en 4.6.1 (dépôt CRAN), sauf
   à le retenir en 4.5 :
   `sudo apt-mark hold r-base r-base-core r-base-dev r-base-html r-recommended`.
   Si un pilote du PPA pose un jour problème, revenir à la Mesa d'Ubuntu
   (25.2.8) : `sudo ppa-purge ppa:kisak/kisak-mesa` (version installée
   0.2.8+bzr63-0ubuntu2.1, qui sait désactiver un fichier `.sources`,
   Launchpad bug 2036761). Simulé : 21 paquets reviennent aux versions
   d'Ubuntu, aucun n'est supprimé.
3. Si R passe en 4.6 : réinstaller les paquets de
   `~/R/x86_64-pc-linux-gnu-library/4.5` (228). 213 viennent du CRAN ;
   15 viennent de GitHub, GitLab, r-universe ou d'une installation locale
   (ASHE, CARD, card4r, cssparser, dataSHEEP, dataverseuR, EXstat, fairy,
   glitter, icons, j2krui, NCf, rnaturalearthdata, shinyWidgets, svgparser)
   et se reprennent un par un.
4. Facultatif : ne plus être averti de 26.04, avec `Prompt=never` dans
   `/etc/update-manager/release-upgrades`.

## Pourquoi maintenant

Le 13 octobre 2026, `do-release-upgrade -c` propose 26.04.1 LTS. La faire
avant l'inventaire des raccourcis et la config de kitty (plan
`2026-10-13_terminal.md`) évite de faire ce travail deux fois, puisque KDE
passe de Plasma 5.27 à 6.6. Elle apporte par apt, sans snap :

| Logiciel   | 24.04 (ici)                    | 26.04                        |
| ---------- | ------------------------------ | ---------------------------- |
| Emacs      | 29.3                           | 30.2                         |
| kitty      | 0.32.2                         | 0.45.0                       |
| Plasma     | 5.27                           | 6.6 (session X11 possible)   |
| Python     | 3.12                           | 3.14                         |
| R          | 4.5.2 (CRAN), 4.6.1 en attente | 4.6.1 (CRAN), 4.5.2 (Ubuntu) |
| PostgreSQL | 16 (+ PostGIS 3.4)             | 18 (+ PostGIS 3.6)           |
| GDAL, PROJ | 3.8, 9.4                       | 3.12, 9.7                    |
| GEOS, ICU  | 3.12, 74                       | 3.14, 78                     |
| Mesa       | 25.3 et 26.0 (PPA kisak)       | 26.0                         |

Versions de 26.04 lues dans Launchpad (série `resolute`) et dans le dépôt
CRAN `resolute-cran40`.

Pas d'urgence, mais une échéance (mesuré le 14 octobre 2026) :

- La base d'Ubuntu 24.04 (dépôt main) reçoit ses correctifs jusqu'en 2029
  (`pro security-status`) ; Kubuntu 24.04, c'est-à-dire KDE, jusqu'en
  avril 2027 seulement (kubuntu.org, trois ans pour les variantes).
- Plasma, Dolphin, Konsole et Emacs viennent du dépôt universe :
  `pro security-status` compte 133 correctifs de sécurité qui ne leur
  parviennent qu'avec Ubuntu Pro (gratuit pour un usage personnel).
- Les correctifs de sécurité gratuits s'installent seuls
  (`unattended-upgrades` actif) : aucune des 190 mises à jour en attente n'en
  est un (comparées au dépôt `noble-security`).

## Bilan du poste, 13 octobre 2026

Sans risque particulier :

- Aucun paquet bloqué ni cassé (`apt-mark showhold`, `dpkg --audit`).
- Kubuntu complet (`kubuntu-desktop`), donc Plasma 6 arrive entier.
- Noyau 7.0 déjà installé (série HWE) : il change peu.
- Pas de module DKMS, Secure Boot désactivé : rien à recompiler pour démarrer.
- Place : `/` 561 Go libres, `/boot` 1,6 Go libres.
- Firefox vient de `/opt/firefox` (archive de Mozilla) : la mise à niveau n'y
  touche pas.
- `ubuntu-release-upgrader` relance la mise à niveau dans GNU screen si
  `screen` est installé (`DistUpgradeMain.py`) : elle survit alors à une panne
  de la session graphique. `screen` n'est pas installé.

Demande de l'attention :

- **Disque chiffré (LUKS, puis LVM)** : sans retour en arrière possible (tout
  le disque est pris, pas d'instantané LVM). Le seul filet est une sauvegarde
  et une clé USB de démarrage.
- **Batterie** : le PC tournait sur batterie (95 %) pendant le bilan.
- **PostgreSQL 16** avec PostGIS, cluster `16/main` dont les données sont sur
  `/mnt/CARGO2`, non monté le 13 octobre (cluster arrêté). 26.04 n'a plus
  PostgreSQL 16 : le paquet reste installé mais devient obsolète. Le retirer
  avant de migrer le cluster le laisserait sans serveur pour lire ses données.
- **R** : les 190 mises à jour de 24.04 font déjà passer R de 4.5.2 à 4.6.1
  (dépôt CRAN). R 4.6 cherche ses paquets dans une nouvelle bibliothèque
  (`~/R/x86_64-pc-linux-gnu-library/4.6`) : les 228 paquets de la 4.5 sont à
  réinstaller. Parmi eux, ceux qui dépendent de bibliothèques du système
  (sf, terra, raster, s2, units, magick, V8, igraph, curl, openssl, xml2,
  ragg, systemfonts, textshaping, stringi, data.table) devront de toute façon
  être recompilés sous 26.04. On les réinstalle donc une seule fois, après.
- **Python** : `~/.python_env` (et `~/.emacs.d/elpy/rpc-venv`, ignoré par
  git) sont bâtis sur Python 3.12, absent de 26.04.
- **Dépôts tiers** (désactivés par la mise à niveau) :

  | Dépôt          | Suite     | Pour 26.04               |
  | -------------- | --------- | ------------------------ |
  | CRAN (R)       | noble     | `resolute-cran40` existe |

  | PPA kisak-mesa | noble     | `resolute` existe        |
  | NodeSource 20  | nodistro  | même ligne, à réactiver  |
  | DBeaver        | générique | même ligne, à réactiver  |
  | Element        | générique | même ligne, à réactiver  |
  | Mattermost     | générique | même ligne, à réactiver  |
  | Steam          | générique | même ligne, à réactiver  |

- **PPA kisak-mesa** : sa Mesa (26.2.4) est plus récente que celle de 26.04
  (26.0.8), ce qui mélangerait deux sources pendant la mise à niveau.
- **Snaps déjà présents** : chromium et cups (hors sujet ici, à revoir avec la
  décision « pas de snap »).
- **Interface Plasma** (relevé le 14 octobre 2026 dans `~/.config` et
  `~/.local/share`). Ce qui vient de KDE suit en principe : position du
  panneau, widgets de KDE, icônes Breeze_Dark_RC, curseur capitaine, polices,

## Ce qui peut arriver

Ce qui toucherait le PC lui-même, rare sur un poste dans cet état :

- **Une interruption au milieu** (coupure, plantage de la session) laisse
  un système à moitié mis à niveau. Se répare en général depuis une console
  texte (Ctrl+Alt+F3) : `sudo dpkg --configure -a`, puis
  `sudo apt -f install`, puis relancer `sudo do-release-upgrade`.
- **Un démarrage qui échoue** (déverrouillage du disque, GRUB) : se répare
  depuis la clé USB, avec la phrase de passe du disque.
- **Pas de retour à 24.04** : seulement réinstaller et restaurer la
  sauvegarde.

Ce qui toucherait le travail, attendu et réparable :

- R sans ses paquets jusqu'à la réinstallation ; venvs Python à recréer ;
  logiciels des dépôts tiers à réactiver ; Plasma 6 qui change l'apparence et
  certains réglages ; Emacs 30.2 à retester.
- Les données de `/home` ne sont pas touchées par la mise à niveau. Le seul
  vrai risque pour des données est le cluster PostgreSQL, si on retire
  `postgresql-16` trop tôt.

## Procédure

Chaque étape : Lou la lance, puis Claude vérifie avant la suivante.

**Avant**

1. Brancher le secteur.
2. Une clé USB de démarrage Kubuntu 26.04.1 (ISO sur kubuntu.org, écrite avec
   ISO Image Writer), et la phrase de passe du disque sous la main.
3. Sauvegarder `/home/lheraut` sur un disque externe, par exemple :
   `rsync -aHAX --info=progress2 --exclude='.cache/' /home/lheraut/ /chemin/du/disque/home-2026-10-13/`
4. Garder quatre listes, dans `~` :
   - `~/.python_env/bin/pip freeze > ~/python_env-requirements.txt`
   - `Rscript -e 'writeLines(rownames(installed.packages(lib.loc = "~/R/x86_64-pc-linux-gnu-library/4.5")), "~/R-packages.txt")'`
   - `apt-mark showmanual > ~/apt-manual.txt`
   - `ls /etc/apt/sources.list.d/ > ~/apt-sources.txt`
   Et une copie de l'interface Plasma, pour retrouver les anciens réglages :
   des captures d'écran du bureau, du panneau et des réglages de chaque
   widget du Store, et
   `tar czf ~/plasma5-2026-10-14.tar.gz -C ~ .config/plasma-org.kde.plasma.desktop-appletsrc .config/plasmashellrc .config/plasmarc .config/kwinrc .config/kdeglobals .config/kglobalshortcutsrc .config/khotkeysrc .config/kcminputrc .local/share/plasma .local/share/kwin`
5. PostgreSQL, si la base sur CARGO2 sert encore : brancher le disque,
   démarrer le cluster, et en faire une copie logique
   (`sudo -u postgres pg_dumpall > /chemin/sur/CARGO2/dump-2026-10-13.sql`).
6. PPA kisak-mesa : le retirer, sauf raison de le garder
   (`sudo apt install ppa-purge && sudo ppa-purge ppa:kisak/kisak-mesa`).
7. `sudo apt install screen`.
8. Mettre 24.04 à jour : `sudo apt update && sudo apt full-upgrade`, puis
   redémarrer.

**Pendant**

9. Dans Konsole : `sudo do-release-upgrade`. Compter une à deux heures, ne
   rien interrompre même si ça semble figé. Si la session graphique se fige :
   Ctrl+Alt+F3, se connecter, `sudo screen -d -r`.
   - Fichier de configuration modifié localement : garder la version
     installée (réponse par défaut, N), sauf avis contraire.
   - « Supprimer les paquets obsolètes ? » : répondre non. On fera le tri
     après, en gardant `postgresql-16` tant que le cluster n'est pas migré.
10. Redémarrer à la fin.

**Après**

11. À l'écran de connexion, choisir « Plasma (X11) » ; s'il manque :
    `sudo apt install plasma-session-x11`. Puis l'interface : remplacer les
    widgets en erreur (tableau plus haut), recréer les raccourcis de KHotkeys,
    remettre le simple clic si voulu.
12. Réactiver les dépôts tiers utiles (tableau plus haut).
13. R : avec CRAN `resolute-cran40`, mettre R à jour (4.6.1), puis
    `Rscript -e 'install.packages(readLines("~/R-packages.txt"), repos = "https://cloud.r-project.org")'`.
    Les paquets venus de GitHub ou de Bioconductor sont à reprendre à la main.
14. Python : recréer `~/.python_env` (`create-python-env` dans Emacs), puis
    `pip install -r ~/python_env-requirements.txt`.
15. PostgreSQL, CARGO2 branché : `sudo pg_upgradecluster 16 main` (vers 18,
    avec `postgresql-18-postgis-3`), ou restaurer la copie logique dans 18.
    Retirer `postgresql-16` seulement ensuite.
16. Vérifier Klipper, Docker, QGIS, Steam.
17. Emacs 30.2 : retester la config (`dev/tty-check.py`, C-z, Python, R,
    export PDF), refaire les mesures de démarrage, puis mettre à jour
    `CLAUDE.md`, `dev/decisions.md` et le plan du terminal.
18. Faire le tri des paquets obsolètes (`apt autoremove`, en relisant la
    liste).
